# opencode 免费通道 TLS 指纹门禁 — 补丁与实测记录

**这是一个补丁 + 技术记录，不是可直接安装的插件包。** 它记录 2026-11-13 在
`dsh-our-free-model` 上定位到的一个门禁问题、实测证据、以及一份可选的绕过实现。

## ⚠️ 使用前必读：本补丁绕过了上游新增的客户端校验

**请你先完整读完这一节再决定要不要用。**

### 1. 这个补丁在做什么

opencode.ai 的匿名免费通道在 2026-11 期间加了一道**客户端身份校验**：它按 TLS 握手的
指纹（JA3）区分「是不是它自己的客户端」，不认识的连接一律返回
`FreeUsageLimitError`（HTTP 429），**与请求内容无关**。

本补丁的做法是：当免费通道返回这个错误时，改为调用**官方开源的 opencode 命令行程序**
（`opencode run --format json`）去完成这一次请求，再把结果转回原有的流式格式。

换句话说：**它让第三方程序借用了官方客户端那条会被放行的连接，从而使用上游原本可能
并不打算开放给第三方的免费额度。**

### 2. 这可能违反上游的服务条款

- opencode.ai 的服务条款与用量政策**由你自行查阅并遵守**。本补丁的作者不是这些条款的
  当事方，也不代表上游做任何解释。
- 上游维护的 `dsh-our-free-model` 在 README 中已明确写明：**「上游条款由你遵守。使用各
  渠道即表示你同意对应上游的服务条款与用量政策；因违反上游政策导致的限流、封禁或其它
  后果由使用者自行承担。」**
- 免费额度是上游**单方面提供、可随时收紧或关闭**的。绕过一道刚加上的校验，很可能正是
  上游试图阻止的行为。
- 若上游因此收紧策略、封禁账号或采取其它措施，**后果由使用者自行承担**。

### 3. 本补丁不承诺任何东西

- 不承诺能用、不承诺能一直用、不承诺不被封、不承诺上游不会改变策略。

### 4. 能力降级（务必知道）

走桥接路径时，**模型决定要用的工具（shell、读写文件等）是由那个官方 agent 自己执行的**，
不是交回你的程序、按你的权限审批链执行的。因此：

- 你拿到的是「已经执行完的结果文本」，不是一次待你批准的工具调用；
- 那些命令**没有经过你自己的审批、沙箱或审计**；
- 你的对话内容会经过官方 client 的完整 agent 流程（它会注入自己的系统提示与工具集）。

如果这不可接受，请**不要启用**这一路径（本文档附带的代码是可选回退，正常直连优先）。

### 5. 不要用它做这些事

- 不要用它做高频/并发批量调用、压测或爬取——这既伤上游也最容易导致封禁。
- 不要用它传输密码、密钥、个人身份信息、商业机密或任何你不愿第三方处理的内容。
- 不要把它包装成「免费无限额度」对外宣传或转售。
- 不要用它访问你不被授权访问的资源。

## 门禁是怎么被定位的（实测记录）

### 同一出口、同一时刻的对照

| 客户端 | TLS JA3 | 密码套件 | 扩展 | 结果 |
|---|---|---|---|---|
| 官方 `opencode` 二进制（Bun 1.3.14） | `4b74b406489f0541b7dd8c6638e9bb88` | 17 | 14 | **200 正常出字** |
| node `fetch`（undici） | `d0642faa769160a231dbd70e346d3790` | 52 | 12 | 429 |
| `bun -e 'fetch(...)'` | `fef5c9001831a7739f735d0b118547ce` | 17 | 13 | 429 |

官方指纹两次独立测量**完全一致**；`bun` 裸跑与官方套件数相同、只差一个扩展就被拒，
说明校验很紧。

### 排除掉的其它可能（都是实测，不是推测）

| 假设 | 反证 |
|---|---|
| 配额用尽 | 同一秒官方成功、第三方 429；跨过 `Retry-After` 反解的 UTC 零点后仍 429 |
| 出口 IP 被封 | 换 4 国 5 个 IP、绕过 TUN 走家宽，全部 429；官方走**同一个代理**仍成功 |
| 请求头/体/路径不对 | 用 MITM 抓到官方真实字节（含 38KB 系统提示 + 13 工具 + `max_tokens:32000`）**逐字节重放**仍 429；两条路径都试过 |
| 插件版本旧 | 已升到 2.8.0（上游 v2.8.3 的发版说明与免费通道无关） |

结论：**闸门在 socket 层，不在应用层**。任何改 header / 改 body / 换 IP 的尝试都不可能通过。

## 如何应用（仅限你确实决定要用的场合）

1. 自备上游插件 `dsh-our-free-model@2.8.0` 并解包。
2. 复制 `src/official-bridge.js` 到 `package/src/`。
3. `cd package/src && patch -p1 < <本仓库>/patches/http.js.diff`
   （补丁已实测：在 2.8.0 原版上应用后与验证过的成品**逐字节一致**）。
4. 确保机器上装有官方 `opencode` 可执行文件；否则用
   `OUR_FREE_MODEL_OFFICIAL_BIN=/path/to/opencode` 指定。
5. 运行 `node tests/official-bridge.test.mjs`，应显示 `9 checks passed`。

改动行为：**正常直连优先**，只有收到 `FreeUsageLimitError` 且本机有官方二进制时才走桥接；
桥接失败会回落到原始错误，不掩盖上游的回应。
